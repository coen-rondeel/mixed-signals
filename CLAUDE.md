# mixed-signals

A JAX package that checks the quality of single posteriors and compares posteriors from different analyses of the same data, reporting every number against a finite-sample null. Built for gravitational-wave data analysis (LISA, LVK), but the core is domain-agnostic.

## Read first

`DESIGN.md` holds the agreed architecture: 354 decisions, the package layout, what is open or deferred, and the sources of every method. Follow it.

`ROADMAP.md` splits the implementation into sessions 0 to 19 and tracks their status. Take the next open session, follow its brief and the routine at the top of the file, and update the status table when done.

- Items marked **Proposed** or **Open** are not agreed yet. Say so when work depends on one, and ask before treating it as settled.
- When a decision changes, update `DESIGN.md` in the same change.
- When a choice is settled neither here nor in `DESIGN.md`, ask the developers before picking one.

## Commands

- `uv sync`: development environment with every extra except the CUDA ones, plus the test and lint tools.
- `uv run pytest`: CPU tests. `uv run pytest -m gpu`: GPU suite, run by hand on a CUDA machine after `uv sync --extra cuda12` or `--extra cuda13`.
- `uv run ruff check`, `uv run ruff format`, `uv run mypy`, `uv run ty check --ignore all --error deprecated` and `uv run python scripts/check_style.py` must all pass; pre-commit runs everything except mypy. ty runs only its deprecated rule, because mypy reverts some typeshed deprecations in its own stubs; mypy stays the type checker.
- `uv run --group docs sphinx-build -W -b html docs docs/_build/html`: docs build, where warnings fail.
- `uv run mixed-signals run CONFIG [--dry-run] [--output DIR] [--overwrite]`: runs a pipeline config and writes its run folder; `--dry-run` prints the estimate of every engine and stops. For the example, `uv run python examples/pipeline/make_data.py` writes its data, and `examples/pipeline/config.yaml` runs in about three and a half minutes.
- `uv run mixed-signals report RUN_FOLDER [--problems VALUE] [--plot-cap N] [--no-html] [--overwrite]`: copies the report notebook into a run folder as `report.py`, writes `report.json` and exports `report.html`, in about 11 s for the example; the page embeds its figures and tables but loads marimo's front end from jsDelivr, so it renders only online. `examples/pipeline/epsilon.yaml` runs `compare` alone with the Sinkhorn divergence at six factors of ε, in about 70 s, for the ε plot of its report.
- `uv run python scripts/build_validation.py`: rebuilds the validation page, its figures and `docs/validation/results.json` in about an hour and a half; run it alone on the machine, because the page prints wall times. `--quick` runs every check in about four minutes, as `tests/test_build_validation.py` does, and `--only LABEL ... --output-dir DIR` reruns single checks into another directory.
- CI (`.github/workflows/ci.yml`) runs the same checks plus the pre-commit hygiene hooks, CPU only, with the tests on Python 3.12 and 3.13. Its actions are pinned by commit SHA with a version comment; update both together.

## Conventions

- uv project (`uv_build` backend), uv ≥ 0.13, Python ≥ 3.12, Apache-2.0. Distribution `mixed-signals`, import `mixed_signals`, CLI `mixed-signals`.
- Core dependencies: jax, ott-jax (pinned at a commit of its main branch until a release fixes its online mode), equinox, jaxtyping, numpy, polars, pydantic, pyyaml and scipy, which JAX requires anyway; `scipy-stubs` in the lint group types it. ott-jax imports jaxopt, whose DeprecationWarning pytest ignores by name. The test group adds emcee, the tests' reference for the autocorrelation function and τ. Everything else is an extra; add each new extra to the `mixed-signals[...]` entry of the `dev` group as well, except the CUDA extras `cuda12` and `cuda13`, which need a CUDA machine. uv takes CPU-only torch from the PyTorch index on Linux and Windows, so the dev environment and CI stay small.
- eryn is the `eryn` extra, from the `feat-jaxpriors` branch of https://github.com/lisa-analysis-tools/Eryn, which holds eryn's JAX-compatible priors, as a uv git source until it is released. eryn-specific code lives only in `io/eryn_backend.py` and `priors/eryn_container.py`, which import eryn inside functions so `import mixed_signals` works without it; `Chains.from_eryn` and `ParamSpace.from_eryn_priors` import those modules lazily. Use `eryn.priors`; `eryn.prior` is deprecated. eryn's chains, bounds and log priors are in its sampling coordinates, and `ErynPhysical` maps them to physical parameters.
- JAX is a hard dependency. Importing the package enables `jax_enable_x64`; work in float64. Re-exports in `__init__.py` go below the float64 switch. Some JAX functions still return int32, such as `jnp.searchsorted`, and JAX divides int32 in float32 even with x64 on: cast integer results to float64 before arithmetic.
- equinox modules for anything that crosses `jit`; pydantic for configs, `ParamSpace` and provenance; polars for result tables, written to parquet.
- jaxtyping shape annotations on every kernel. The pytest configuration runs beartype on every annotated function in `mixed_signals`; library code never imports beartype.
- jaxtyping dimension names are words: `batch posterior sample param` for the (B, K, N, D) axes of `DESIGN.md`, and `step temp walker leaf param` for eryn chains, for example `Float[Array, "sample param"]`. So far thirteen more exist: `*leading` for any leading axes of a kernel, `selected` for positions picked from an axis, `component` for the components of a mixture, `other` for the axis of a second set, such as the components of a second mixture or the samples of a second posterior, `euclidean`, `circle` and `sphere` for the Euclidean block, the circles and the spheres of a space, `direction` for the directions of sliced metrics and of mode projections, `lag` for the lags of an autocorrelation function, `draw` for the draws of a null, `pair` for the parameter pairs of the dependence diagnostics, `grid` for the points of a grid, and `data` for the entries of a whitened data vector. Add new words sparingly and reuse them across modules; `_` marks an axis that a private helper leaves unchecked, such as eryn's full parameter vector. Ruff ignores F722, because shape strings are not Python; write a single-word shape with a leading space, such as `" sample"`, so that F821 does not read it as a name.
- Google-style docstrings: ruff `D` rules with the google convention, rendered by Sphinx napoleon. Do not put a symbol between bars, such as an absolute value: Sphinx reads it as a substitution and the docs build fails.
- Tests mirror `src/` under `tests/`. mypy reads test files as top-level modules, so their names are unique across `tests/`, and shared fixtures live in `tests/conftest.py`. GPU tests live in `tests/gpu/` and carry `pytestmark = pytest.mark.gpu`. Warnings fail a test unless it expects them.
- Every stochastic function takes an explicit JAX PRNG `key`; pipelines derive all keys from one config seed. Derive each key with `prng.derive_key` from a path of names, never by counting calls, so that keys do not depend on call order.
- Raise package warnings from the classes in `errors.py`, outside jit, where a cached call would not warn again; engines capture them per row with `errors.capture_warnings`.
- Do not annotate with `typing.Self`: beartype rejects it in classes that it does not decorate, and the test hook decorates functions only. Write the class name instead.
- The test hook checks the arguments of an equinox module's own `__init__`, not its field annotations, so containers check their shapes themselves. They check values only for concrete inputs, since traced values are unknown inside `jax.jit`. Inside `jax.jit`, `jax.lax.map` and `jax.lax.scan` no value check runs, also on a concrete array that the traced function closes over, where the check would be staged: guard every such check with `core.samples._is_concrete`, which is false there. Annotate inputs whose dtype and shape the code checks with broad types, so that tests reach the package's own messages.
- Engines (`diagnose`, `compare`, `reweight`, `compare_signals`) are plain functions that return results.
- Nearest-neighbour estimators, the KSG mutual information included, need equally weighted samples without copies: convert a weighted set with `core.samples.rejection_subset`, never by resampling with replacement, whose copies make kNN estimates NaN or biased.
- Every comparison returns a finite-sample null plus σ_sig and an effect size: σ_eff, or r_eff for rows that measure only a difference in width. Pass/fail thresholds act on the effect size.
- Every diagnostic, metric, estimator and null cites the paper, official document or reference package that defines it, in a Google-style `References` docstring section with `:cite:t:` roles and keys from `docs/references.bib`. Keys are first author, year and first significant title word in lowercase ASCII, skipping a leading article, preposition or verb, such as `mardia2000directional` and `kullback1951information`. Every assumption (a default, a threshold, a σ_eff or r_eff map, a null construction) cites a paper or a section of the validation page. `DESIGN.md` lists the sources of every v1 method; a new method needs a verifiable source before it lands, and a citation is never guessed.
- Both inputs to a comparison share one whitening, recorded in the result.
- Never assume user code is JAX: generators and likelihoods may be CuPy or PyTorch and are called at the boundary, through `io.arrays.call_in_chunks`. Noise models whiten templates in the caller's library, so only real rows cross into JAX.
- YAML configs, argparse CLI, Sphinx docs. A pipeline config mirrors the keywords of the engines and names user code by import path `module:attribute`; the reference of its format is the docstring of `pipeline/config.py`.
- Readers of files are classmethods on the core objects, with their code in the `io/` module of the format: `SampleSet.from_npz`, `from_table` and `from_hdf5`, `Chains.from_npz` and `Chains.from_eryn`. Files that name their columns (tables, HDF5 groups, eryn runs) are read by the names of the space; `.npz` and `.npy` arrays are read in order. `SampleSet.to_npz` writes the archive that `from_npz` reads, one posterior per file, which the pipeline uses for `samples/`.
- The report needs the `report` extra (marimo and cantuccio); neither `import mixed_signals` nor `mixed-signals run` imports it. Its figures are `matplotlib.figure.Figure` objects built without pyplot, under `report._style.REPORT_STYLE`, which also goes to cantuccio, whose own style switches LaTeX on. Every table, figure and section is a tested function of `mixed_signals.report`; the notebook `report/notebook.py` only calls them and leaves the coverage measurement.
- GPU tests are a marked suite, run by hand; v1 targets a single GPU.
- The developers own optimal-transport method choices: propose options rather than picking one.

## Style rules

These apply to code, docstrings, comments and documentation; `scripts/check_style.py` enforces the mechanical ones.

- Plain language (ISO 24495) in a scientific register, as a gravitational-wave data analyst would write it.
- No em-dashes and no emojis. Docstrings may use Unicode mathematics such as σ, ρ, π and −; ruff allows σ, ρ, α, ν, ℓ and − as confusable characters.
- No one-letter names for variables, parameters, attributes, functions, classes or type parameters (`_` is fine). Abbreviations are allowed with a short comment that expands them.
- Number literals with five or more digits in a row use `_` separators: `10_000`, `0.000_01`.
- Comments are one or two lines and explain why, not what. Use Better Comments tags where they help: `# !` warning, `# ?` question or uncertainty, `# *` highlight, `# TODO` gap. Longer explanations belong in the docs.
- State reasons directly; never justify a change by pointing at a label in another document, such as a question number.
- Refer to "the developers", not to a person by name; the README author line and the commit trailers are the exceptions.
- A line containing `# style: allow` is exempt from the name and number rules; use it only when an external API forces the name.
